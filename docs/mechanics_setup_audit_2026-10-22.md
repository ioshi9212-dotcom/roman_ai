## Что мешало до первой сцены

| Проблема | Наблюдение | Исправление |
|---|---|---|
| Новая анкета попадала в старый сценарий | Статический OpenAPI обещал default=5, `NovelDraftCreate` и `create_draft` использовали default=1. Запрос без version включал старые обязательные разделы. | Оба серверных значения по умолчанию — 5. Явные версии 1–4 остаются совместимыми. |
| Сохранение раздела требовало неописанную revision | Для V5 сервер требовал `expected_revision`, но инструкция GPT не сообщала о ней. | Порядок ревизий указан в GPT, Rules, OpenAPI и profile_schema. Последовательные записи используют последнюю revision/draft_revision. |
| Формат файлов смешивался с форматом Actions | Инструкция требовала десять JSON, хотя API принимает разделы novel/characters/knowledge и т. д. | profile_schema теперь явно описывает входные разделы и поясняет, какие файлы создаёт сервер. |
| В русском шаблоне анкеты не было POV | Обязательный `pov_character` отсутствовал в анкета.json. | Добавлен `pov_id`, преобразуемый в канонический pov_character, с обратным сохранением в русский файл. |
| Повторяющиеся ID и неверные типы теряли сведения | Нормализатор молча пропускал дубликаты карточек, превращал неправильный novel/knowledge в пустой объект. | V5 отклоняет такие записи до изменения черновика. Недопустимые ID файлов выявляются до создания сессии. |
| Несколько POV выбирались по порядку карточек | Несогласованные pov_character/is_pov не проверялись. | Возвращаются DRAFT_POV_UNKNOWN, DRAFT_POV_AMBIGUOUS или DRAFT_POV_CONFLICT. Финальный профиль содержит один канонический ID. |
| Finalize скрывал причину остановки | Разные ошибки возвращались как `Draft is incomplete`. | Клиент получает точный код блокирующего условия. Ответ finalize содержит finalized_revision для запуска. |
| Метаданные шаблонов могли стать каноном | `_памятка` попадала в additional или записи лора/заметок при нормализации шаблонов. | Служебные поля не переносятся в профиль. Дословный RAW хранится отдельно без изменения. |
| Повтор стартового запроса ломался после commit | Проверка «opening только на turn=0» выполнялась раньше поиска сохранённого request_id. | Точный повтор сначала получает сохранённый результат; новая команда открытия после первого хода отклоняется. |

Памятки `state/отношения.json`, памяти и хронологии также требовали устаревшую стартовую сверку с цитатами, дополнительные reviews и обязательные операции на 15/60. Эти требования удалены. Памятки всех десяти шаблонов описывают хранение и соответствие API.

## Где находятся действующие инструкции

| Источник | Ответственность |
|---|---|
| `runtime/scene_builder.md` | Единственные общие правила написания сцен: POV/NPC, последовательность ввода, приватность мыслей, визуал, темп, варианты и оформление ответа. |
| `runtime/rules.md` | Создание и чтение черновика, источники данных, личные знания, состояние, отношения, persistence, commit и ручной аудит. |
| `gpt/custom_gpt_instructions.md` | Порядок вызовов Actions, ревизии, чтение, сохранение, продолжение и откат. |
| `state/*.json` | Схемы постоянных файлов и технические памятки. Сервер формирует реестр и личные файлы. |
| `app/turn_pipeline.py` | Один действующий игровой pipeline. Передаёт данные, проверяет согласованность и сохраняет изменения. |

Из Rules перенесены в Scene Builder правила границы хода, обработки ввода, первого впечатления и видимого footer. Из `waiting_momentum.writer_cue` удалена режиссёрская инструкция: в packet остаются только вид ввода и число последовательных ожиданий. Правила ожидания находятся в Scene Builder. Отношения и cast registry больше не передают отдельную режиссёрскую политику.

Подключение в `app/__init__.py`: четыре адаптера setup/совместимости и один `turn_pipeline.install()`. Название файла `*_runtime.py` само по себе не означает отдельный набор инструкций. Модули чтения, личной памяти, отношений, транзакций и отката нужны для механики.

Исторические `narrative_guardrails_runtime`, `runtime_contract`, `scene_logic_runtime`, `living_world_runtime`, `relationship_policy_runtime` и `relationship_growth_runtime` не установлены в действующий pipeline. Их старые проверки не возвращаются в игровой packet. Архивные инструкции и тесты прошлых API не являются источником правил текущей сессии; они сохранены для совместимости и истории изменений. Правила конкретного автора в загруженном RAW остаются его данными, а не новой встроенной системной инструкцией.

## Проверка механики

Новый `tests/test_setup_actions_e2e.py` использует настоящий FastAPI TestClient и публичные HTTP-маршруты Actions:

1. Создание черновика без указания version.
2. Однократная дословная загрузка длинного RAW, SHA256, повтор без новой записи.
3. Сохранение русского шаблона анкеты и персональных карточек; направленные стартовые отношения и личные знания.
4. Явный отказ finalize до полного чтения; продолжение того же read_id с очередного chunk.
5. Reconciliation, finalize, launch state, идемпотентное создание сессии.
6. Resume до первого хода и полное чтение отсутствующего NPC через bundle.
7. Подготовка и commit 61 последовательного хода через HTTP с тремя review-флагами.
8. Повторы prepare/commit, включая уже сохранённый opening и поздний повтор первого commit.
9. Сохранение факта только получателю, хронологии и дробного изменения отношения.
10. Продолжение на 15/45/60 без автоматического аудита или блокировки.
11. Точный откат последнего хода и повтор отката.
12. Явный ручной аудит первого накопленного окна и подготовка следующего хода.

Дополнительные случаи проверяют неверные типы, дубликаты и недопустимые ID, отсутствие revision, конфликтующие POV и совпадение default в статическом и живом OpenAPI.

Существующий набор current-runtime дополнительно проверяет длинную сессию на 300 ходов, файлы знаний, приватные сведения, physical/remote presence, intents/threads, восстановление, транзакции, продолжение, аудит и откат. Устаревшие проверки конкретных фраз заменены проверками принадлежности правил правильному документу; произвольный SHA текста автора больше не блокирует его редактирование.

До изменений: current-runtime — 350 passed / 7 failed; полный исторический набор — 480 passed / 160 failed. Все семь current-падений требовали формулировки уже удалённой версии Scene Builder. После изменений: current-runtime вместе с проверками источников и ожидания — **388 passed**; дополнительные проверки legacy-создания и чтения — **13 passed**. Статический OpenAPI валиден; инструкция GPT укладывается в 8000 символов, включая CRLF. Полный historical-reference набор сохраняет отдельные прежние падения по удалённым контрактам; его итог и сравнение с исходным набором приведены в PR.

Это проверка API и хранения. Она не является проверкой качества сцены, сгенерированной языковой моделью по конкретному пользовательскому TXT.
