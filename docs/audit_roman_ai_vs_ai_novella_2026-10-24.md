## II. Подтверждённые проблемы Roman AI и действия в ветке

### P0: расходились реальный формат сцены и валидатор

`runtime/scene_builder.md` использовал заголовок `**◈ ...**`, `◷ День`, `⌖`, `▸`, `◇`, `▣`. `app/scene_format.py` проверял только старый `🎭`, `🕒`, `🌦️`, `✦`, `🧥` и один старый разделитель. Исправлено: поддерживаются оба формата, декоративная линия нового header отделена от настоящей границы основной сцены. Регрессионный файл `tests/test_scene_format_current_builder.py`.

### P1: тяжёлые и конфликтующие художественные правила

Старый Builder занимал более 20 тысяч символов и одновременно требовал обязательного прогресса на каждом ходе, обязательного преодоления «застоя» за 2–3 хода и сохранения непрерывных эпизодов. Это прямой конфликт целей: модель склонна ускорять сцену, когда уже возникло интересное взаимодействие. Новый `runtime/scene_builder.md` около 9 тысяч символов: нет квоты эскалации, диалог может идти несколько ходов, у NPC сохраняются характер и самостоятельная инициатива, очередной ход заканчивается без обязательного завершения сцены. Формат реплик восстановлен: **Имя**, *курсивная реплика*, (ремарка). Убраны инструкции про CSS, цвет чата, «пузырьки», когда рендер должен делать UI.

### P1: выпадение конкретного диалога из рабочего контекста

В `app/writer_first_runtime.py` компактный ход раньше включал `scene_tail` только **если** не было chronology/presence/relationship updates. В результате чаще всего содержательные события получали сухой список фактов, а слова, тон и реакция исчезали из контекста. Исправлено: храним короткий отрывок **тела сцены**, даже когда присутствуют структурные факты. Убираем варианты из хвоста сцены: они ещё не случились и не могут становиться воспоминаниями. Приватная коммуникация по-прежнему должна проходить через `private_knowledge_runtime.redact_private_history`. Две полные последние сцены оставлены: временное увеличение до четырёх сломало бюджет пакета и несколько проверок границы конфиденциальности; изменение откатили. Добавлен `tests/test_continuity_dialogue_excerpt.py`.

### P1: незаметная правка авторской анкеты при нормализации

`normalize_novel_profile` вырезал из авторского `story_rules` фразу, которая совпадала с устаревшим игровым правилом про молчание POV. Это нарушало принцип «хранить дословно». Убрана правка *при записи оригинала*; техническое устаревшее правило можно исключать только из **производного контекста писателя**, не из источника. Добавлены `tests/test_verbatim_canon_preservation.py` и уточнение `tests/test_profile_templates.py`.

### P2: сценарный контракт был жёстко привязан к старым текстовым формулировкам

Часть тестов требовала буквального сохранения прежней команды NPC нарушать границы, вместо проверки независимого поведения по характеру. Тест обновлён для проверки самостоятельности NPC и отсутствия превращения всего каста в одинаковых агрессоров. Художественные правила по-прежнему единственный источник `runtime/scene_builder.md`.

## III. Новая база данных сюжета, пока НЕ подключена

Только черновики: `drafts/novel_foundation/`.
- `character_card.v1.json` и `novel_profile.v1.json`: дословные фрагменты RAW, тематические индексы по ID, отдельный неизменяемый источник, запрет смягчения.
- `personal_memory.v1.json`: факт/утверждение + источник, личный опыт, важная дословная реплика, обещание и незакрытый вопрос.
- `relationships.v1.json`: индивидуальные направленные отношения, причины и доказуемые изменения.
- `scene_state.v1.json`: точный момент, позиции, вещи, приватность звонков и незавершённые действия.
- `chronology.v1.json`: реально произошедшее, причинность и последствия; не раздаёт знания NPC.
- `hidden_lore_threads.v1.json`: режиссёрская истина vs незакрытая ситуация vs планы конкретного NPC.
- `locations.v1.json`: география и неизменные свойства мест отдельно от текущих изменений.
- `verbatim_source_contract.md`: сохранение дословного RAW и будущая доказательная сверка цитат.

**Не внедрять эти v1 файлы механически в действующий V5 формат**: существуют нормализаторы, совместимость миграций, постоянные ID, ссылки, формат commit и API. Пока новые JSON документы не участвуют в рабочем игровом цикле, они служат договором на следующую итерацию.

## IV. Что действительно проверяется автоматически

GitHub Actions `.github/workflows/tests.yml` исполняет большой набор регрессионных тестов, включая хранение RAW, setup/finalize, текущие сессии, память, отношения, приватность, архивы, повторы prepare/commit, длительный цикл, rollback. `.github/workflows/scene-refactor-smoke.yml` проверяет правила/поверхность GPT и формат. Ветку добавили в triggers `push`, а в current-runtime добавили собственные регрессии. `choice-ui` проверяет интерактивный выбор; исторический `legacy-reference` разрешён как reference с `continue-on-error`.

Отдельно проверяли в GitHub Actions: commit `dae67092` — новый формат/legacy scene green, `74a85bb` — smoke + current-runtime green. Новые тесты проходят лишь тогда, когда их соответствующий run завершился `success`; статус конкретного последнего коммита нужно брать из GitHub Actions, а не из намерения.

## V. Что ещё **не подтверждено** и не должно выдаваться за исправленное

1. **Смысловая дословность анкет:** сервер хранит исходный RAW дословно и умеет его прочитать; но отметка `reviewed_against_raw=true` в V5 — ручное утверждение, которое само по себе не доказывает, что каждая жёсткая реплика, порок, внешняя деталь и биография попали в карточку без пересказа. Для гарантии нужна проверка provenance-цитат/полноты покрытия RAW на этапе finalize. Новые v1 шаблоны предлагают механизм, но ещё не включены в backend.
2. **Качество художественных сцен:** тесты проверяют структуру и сохранение, но не могут подтвердить, что GPT художественно оживил всех NPC, выдержал ритм и дал интересный диалог. Нужно 10–20 реальных последовательных ходов с разными отношениями, затем читательский аудит.
3. **Развёртывание:** нет доказательства, что исправленная ветка опубликована в Amvera. Её **нельзя считать доступной в существующем Custom GPT**, пока не развёрнута отдельная тестовая копия и не обновлены Actions/документы.
4. **Старые сессии:** автоматическая миграция между шаблонами v1 и Roman V5 не реализована. Не подключать реальный persistent `/data` к экспериментам без резервной копии.
5. **Объём технических инструкций:** `runtime/rules.md` всё ещё содержит подробные инструкции транспорта, состояний и сохранения. В этом проходе не удалялись критичные механизмы хранения без покрывающих проверок; для дальнейшего уменьшения packet нужен отдельный безопасный рефакторинг без дублирующих директив.
6. **Здесь не создана новая игровая сессия:** для неё потребуются выбранный конкретный исходный роман/RAW, согласованные данные и отдельный runtime тестового сервера. Ни один вымышленный сюжет не был запущен автоматически.

## VI. Порядок безопасного запуска после проверки CI

1. Посмотреть GitHub Actions **именно на последнем SHA** ветки. Исправить failing current-runtime/smoke до тестового развёртывания.
2. Поднять **отдельную** тестовую инсталляцию Amvera из экспериментальной ветки со **своим** томом `/data`, не изменяя production `main`.
3. Проверить `/health`, schema Actions и runtime_revision тестового URL.
4. Загрузить исходный RAW через API, проверить хеш/размер/повтор чтения, сравнить с действительно заполненными карточками.
5. Начать тестовую историю на этом сервере: 10–20 последовательных ходов, проверить текст, доступность контекста, память, отношения и rollback. После этого решать об интеграции v1 схем.

**Итог:** ошибки формата, ненужное сюжетное принуждение и часть потери диалоговой непрерывности устранены в изолированной ветке; подготовлены полные черновики данных. Превращать это в заявление «уже можно читать работающую новеллу в production» было бы неверно.
