# MEMORY CONTRACT

Не смешивай четыре разных вещи.

## CARD
Кто персонаж вообще: личность, характер, биография, прошлое, привычки, устойчивые цели и важные связи. Полные карточки живут в `characters.json`. Они не переписываются каждый ход.

Card — объективное авторское знание. Факт из Card НЕ становится знанием другого персонажа автоматически.

Если во время игры появляется новый recurring/important NPC, сохрани его через `character_upserts`. Одноразовый фоновый человек карточки не требует.

## STATE
Что с персонажем сейчас: место, присутствие в сцене, физическое состояние, текущая цель/статус, предметы и другое временное состояние. Это `state.json`.

## CHRONOLOGY
Что объективно произошло в мире.

Chronology нужна автору для непрерывности. Она НЕ является памятью персонажей и НЕ сообщает, кто знает записанный факт.

Даже если событие есть в chronology, персонаж может использовать его в речи, выводах и решениях только если он лично видел/слышал/получил это в сцене либо соответствующее знание уже сохранено в его PERSONAL MEMORY.

## PERSONAL MEMORY
Для каждого персонажа отдельно:

### knowledge
Что именно этот персонаж знает или считает правдой.
Поля по возможности: `fact_id`, `content`, `source`, `learned_turn`, `confidence`.

### experiences
Что именно этот персонаж лично видел, слышал, сделал, получил или пережил.
Поля: `event_id`, `turn`, `summary`, `role`.

### dialogue_memory
Важные темы разговоров, в которых именно этот персонаж участвовал или которые лично слышал: вопросы, ответы, обещания, отказ, ложь, незакрытая тема.
Поля: `topic_id`, `turn`, `asked_by`, `asked_to`, `question`, `answer`, `status`.

## КТО ЧТО ВИДЕЛ И СЛЫШАЛ
На каждом ходу проверяй персонажей сцены ПО ОТДЕЛЬНОСТИ.

Для каждого персонажа:
1. был ли он физически присутствующим в момент события/реплики;
2. мог ли он это увидеть или услышать;
3. получил ли он сообщение, предмет или информацию другим прямым способом;
4. только после этого сохраняй `knowledge_add`, `experiences_add` или `dialogue_memory_add` именно ему.

Персонаж, которого не было рядом, ничего не узнаёт автоматически.
Персонаж, пришедший позже, не слышал разговор до своего появления.
Персонаж, ушедший раньше, не знает произошедшего после ухода.
Разговор один на один не раздаёт сведения остальным NPC через chronology.
Если информация была передана позже другим персонажем, это отдельный источник знания.

## ПРАВИЛА
- У каждого персонажа своя память. Не копируй знание между персонажами без источника.
- Перед каждой репликой, вопросом, догадкой, узнаванием или осознанным действием NPC проверяй его `personal_memory`.
- `chronology`, `recent_turns`, Card, hidden lore, source canon и чужая memory не являются источниками персонального знания.
- Ложь хранится как то, что слушателю сказали, а не автоматически как мировая истина.
- Лично пережитое не исчезает только потому, что прошло много ходов.
- Уже отвеченный вопрос не повторяется случайно. Повтор возможен намеренно: сомнение, проверка, давление, изменившиеся обстоятельства, прошлый partial/refused/lie или установленная проблема памяти.
- Старую память не удаляй из-за временной нерелевантности.
- Card задаёт характер и прошлое; memory даёт доступные персонажу знания и пережитый опыт; state показывает настоящее; chronology хранит объективную историю только для автора.
