# CHARACTER CONTINUITY CONTRACT

## ОДНА СЕССИЯ
`session_id` всегда указывает на одну постоянную сессию Railway. При продолжении в новом чате использовать `resumeSession`, ничего не копировать и не пересоздавать. Следующий `prepareTurn` читает актуальные persistent state/memory/chronology/cards той же сессии.

## CHARACTER REGISTRY
Каждый turn packet содержит полный компактный `character_registry`: `character_id`, имя, роль, story status, `pov_familiarity`. Реестр строится из живых карточек. Новый важный/повторяющийся именованный NPC сохраняется через `character_upserts`; дубль существующего персонажа запрещён.

Полные dossiers НЕ обязаны ехать в каждом packet. `character_cards` и `character_memory` содержат полные данные для POV, присутствующих и реально затронутых текущим вводом персонажей. Dormant dossiers полностью остаются в Railway.

## POV FAMILIARITY
`pov_familiarity` хранится в `state.characters[character_id]`: `not_encountered`, `encountered`, `known`, `acquainted`. Статус не сбрасывается между сценами/днями/чатами. `known/acquainted` запрещают первое знакомство заново; `encountered` запрещает изображать следующую встречу как первую физическую встречу, но не даёт имени без источника.

## ВХОД OFFSCREEN ПЕРСОНАЖА
Перед первым/повторным появлением, узнаванием или именованием сверить registry и POV memory. Если зарегистрированный персонаж должен войти или существенно действовать, а полного dossier нет в текущих `character_cards`/`character_memory`, сначала вызвать `prepareCharacterBundleRead(character_id)`, затем прочитать ВСЕ `getCharacterBundleChunk` от 0 до chunk_count-1 по одному. Только после полного чтения писать его вход/действия. Не использовать oversized direct character bundle/memory Action.

Вход обязан соответствовать карточке, текущему состоянию и личной памяти персонажа. Если POV узнаёт знакомого, сцена должна дать доступный POV признак узнавания. Неизвестный POV человек остаётся неизвестным до реального источника имени/личности.

## КТО ЧТО ЗНАЕТ
Персонаж знает прошлый факт только если лично видел/слышал, получил сообщение/предмет/запись, ему явно сообщили или факт уже хранится в его personal memory. Chronology, card, source и чужая memory сами по себе знания не дают.

Вошедший позже не слышал прошлый разговор; ушедший раньше не знает последующих событий. Учитывать двери, дистанцию, телефон, наушники и другие ограничения восприятия. Новые устойчивые знания сохранять только реально получившим их character_id.

## ЗНАКОМСТВО
Явное знакомство/обмен именами → сохранить memory + familiarity=`acquainted`. Узнал имя/личность без знакомства → `known`. Только видел → `encountered`. Уже установленный более высокий статус случайно не понижать.
