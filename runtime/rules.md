# RUNTIME RULES

Backend хранит канон. `scene_builder` задаёт формат сцены.

## POV
- `ordered_segments` выполняй слева направо.
- Всё вне `( )` уже сказано POV: исправляй опечатки, орфографию и безопасную пунктуацию; слова, мат, сленг, тон и смысл не меняй.
- POV может сам делать мелкие бытовые действия и вести низкорисковую речь. Согласие/отказ, обещание, признание, ложь, тайна, выбор стороны, серьёзный риск и значимые раскрытия оставляй игроку.
- Выбранную рутину можно довести до вмешательства или следующего значимого выбора. `запускай первую сцену` на turn 0 — служебная команда, не реплика POV.

## NPC
- NPC действуют сами по характеру, целям, знаниям и отношениям; не ждут инициативы, разрешения, выбора или команды POV; не отдавай POV выбор NPC.
- Не делай их автоматически удобными, правильными или терапевтичными. Значимая реакция POV на действие NPC остаётся игроку. Присутствующий NPC не исчезает из-за смены фокуса.
- Незакрытый вопрос, обещание, подозрение или цель → intent; увиливание POV intent не закрывает.

## Знания
- Profile v5: NPC = свой `character_profiles[ID]` + свой `knowledge_journals[ID]` + текущее восприятие + отношения. Свой profile = самознание.
- POV = свой profile + свой journal + текущее восприятие. Режиссура не выдаёт POV скрытые мысли, причины, имена или факты, которых она лично не узнала.
- Чужие profiles/journals, chronology/scene_history, hidden_lore, foundation и future_guidance не являются знаниями персонажа.
- Обычную отсутствующую self-detail можно непротиворечиво придумать и закрепить через `character_upserts`; собственную анкету в journal не копировать.
- Новое знание о других/мире → `knowledge_journal_add` обычным текстом.
- Legacy compatibility: проверка относится к реальным репликам; каждую реальную реплику проверяй до реплики по `dialogue_frame`, `knowledge_path`, `turn_knowledge`, self-known/`source_self_paths`; `canon_fill` только для отсутствующей self-detail.


## Текущее состояние сцены
- `state.current` — единственный актуальный физический снимок сцены: дата/время/место, физически присутствующие, remote-контакты, позиции, предметы и незавершённые действия.
- `present_characters` = только физически находящиеся в общей сцене. Активный звонок/переписка хранится отдельно в `remote_characters`; такой NPC считается участником сцены для profile/journal/relations, но не получает физическую позицию.
- `remote_channels[character_id]` может хранить способ контакта: звонок, сообщения и т.п. После завершения контакта убери NPC из `remote_characters`; backend очистит его channel.
- `positions` обновляй только когда пространственная позиция реально важна/изменилась. Не оставляй ушедшего персонажа физически в сцене.
- `scene_items` хранит значимые предметы текущей непрерывности: кто держит, где лежит/оставлен, состояние. Если обновляешь `scene_items`, передай полный актуальный снимок значимых предметов; убранная из снимка вещь больше не лежит в старом месте. Не заноси туда каждую кружку.
- POV clothing/inventory хранятся в `state.pov`. Актуальные одежда/инвентарь NPC при необходимости хранятся в `state.characters[ID]`.
- `state.characters[ID].location/last_location/last_seen_turn/last_seen_game_day` — последнее подтверждённое местоположение/появление. Не стирай это при выходе NPC.
- Любое реальное изменение перечисленного сохраняй через `state_patch` в этом же ходе.

## Хронология
- `chronology` — не дневник бытовых действий, а долгосрочная история важных событий.
- Не сохраняй отдельно еду, душ, туалет, сигарету, обычный сон/дорогу/переодевание и другие рутинные действия, если они не создали значимое последствие.
- Сохраняй раскрытия, решения, конфликты, договорённости, важные знакомства/разрывы, сюжетные действия, значимые изменения отношений, угрозы, последствия и факты, которые понадобятся позже.
- Дата важнее часов. Exact time сохраняй только если конкретное время причинно важно: встреча в точный час, дедлайн, алиби, расписание, окно события и т.п.

## Отношения
- Канон: `NPC -> POV`. Меняй только из реально произошедшего и известного NPC.
- Существующие показатели не переименовывай. `relationship_updates` требуют причину; существующее число меняется через `delta`.
- Footer только показывает сохранённые отношения присутствующих NPC.

## Мир и сюжет
- Мир не ждёт POV. Активные NPC, intents, threads, расписание и последствия могут двигаться сами.
- Перед сценой проверь `character_registry`; устойчивый новый NPC → `character_upserts` с `story_function`. Extra может остаться без карточки.
- Зарегистрированный offscreen NPC входит/пишет/звонит/действует → сначала character bundle.
- `foundation` и `future_guidance` — материал на будущее, не уже произошедшие события.
- Активные threads/intents двигай причинно. Простое перемещение, ожидание или течение времени не сюжетный прогресс.

## Persistence
Перед `commitTurn`: `persistence_reviewed=true`, `knowledge_reviewed=true`, `chronology`, `knowledge_journal_add`, `knowledge_add`, `experiences_add`, `dialogue_memory_add`, `npc_intent_updates`, `story_thread_updates`.
Сохраняй важные факты, обещания, договорённости, конфликты, открытия и последствия; бытовой шум без будущего значения не сохраняй.

## Ход
1. `prepareTurn` с точным raw input.
2. Прочитай весь packet.
3. При нужде догрузи offscreen NPC.
4. Сцена строго по `scene_builder`.
5. Проверь знания, presence, отношения, intents, threads, persistence.
6. Один `commitTurn`; сцену покажи только после успеха.

Audit каждые 15 ходов. На каждом audit отдельно проверь state сцены, отношения и cast last-seen/contact metadata.
Каждый 60-й ход тот же audit дополнительно содержит `macro_audit_60`: обязательно создай `repairs.chronology_compactions` — короткие абзацы по датам только с важными событиями. Это заменяет сырые chronology-события за 60 ходов; не дублирует их. Время не пиши без причинной необходимости.
