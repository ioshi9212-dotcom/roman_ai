# RELATIONSHIP CONTRACT

Это глобальная модель отношений, перенесённая из старого генератора.

Отношения являются направленным внутренним состоянием NPC и одной из причин его поведения, а не декоративными числами после сцены.

Основная игровая связь: `NPC -> POV`. POV -> NPC не назначать. В видимом footer показывать только присутствующих NPC -> POV.

## ПРИОРИТЕТ
`relationship_lens` + этот contract являются авторитетной моделью отношений.

Если в packet есть совместимый диагностический `authoritative_start_snapshot`, он показывает сохранённые стартовые числа, но не заменяет `relationship_lens`.

## RELATIONSHIP LENS
Каждый turn packet содержит `relationship_lens` для текущей сцены.

Для уже установленной связи там могут быть:
- `relationship_type`;
- `relationship_context`;
- `current_dynamic`;
- независимые `dimensions` с `key`, `label`, `value`;
- `beliefs_about_target`;
- `unresolved_between_them`;
- `dynamic_constraints`;
- `last_changed_turn`.

`present_npc_candidates` перечисляет присутствующих NPC, в том числе тех, у кого числовая связь ещё не появилась.

Перед реакцией, репликой, инициативой, решением или интерпретацией NPC учитывай его сохранённые dimensions вместе с характером, целями, знаниями и текущим состоянием.

Один показатель не диктует одно обязательное действие. Ревнивый персонаж может скрыть ревность. Высокое доверие не делает его послушным. Близость не отменяет конфликт.

Отсутствие dimension НЕ означает ноль. Не создавай `интерес` или другой показатель как универсальную заглушку.

## КАК ПОЯВЛЯЮТСЯ НОВЫЕ ОТНОШЕНИЯ
Если у присутствующего NPC ещё нет сохранённых dimensions, числовой baseline ещё не создан. Это нормально.

Оцени реальное отношение NPC к POV по характеру, целям, знаниям и текущему взаимодействию. Когда сцена действительно формирует направленное состояние, создай 1–3 естественных dimensions: например симпатия, настороженность, раздражение, уважение, доверие, подозрение, влечение, ревность, обида, страх, привязанность, близость.

Первое содержательное знакомство, конфликт, помощь, флирт, подозрение, сильное впечатление или близость могут создать показатель. Но одно только физическое присутствие рядом с POV НЕ требует придумывать числовое отношение.

Для впервые созданного показателя дельта необязательна, потому что предыдущего сохранённого числа нет. Допустимо:
`Эдриан - симпатия 12; настороженность 8`

После этого dimensions становятся сохранённой связью и продолжаются дальше.

## СОХРАНЕНИЕ
Установленные dimensions не исчезают из-за ухода NPC, смены сцены, дня, чата или временного отсутствия.

Не пересоздавай отношения при возвращении персонажа и не заменяй старый набор показателей новым набором слов. Сначала продолжай существующие dimensions из `relationship_lens`.

Новый показатель добавляй только если он действительно естественно возник именно в этой связи. Несколько независимых показателей могут существовать одновременно и меняться отдельно.

Не менять числа автоматически каждый ход. Обычное изменение за ход 0–3. Больше только при действительно сильном событии. Разрешены отрицательные изменения.

Если сцена не изменила показатель, он сохраняет прежнее значение.

## FOOTER
Формат:
`Имя NPC - показатель число/дельта`

Пример:
`Райан - доверие 10/+1; обида 34/-2`

Если дельты нет:
`Райан - доверие 10; обида 34`

Для присутствующего NPC с уже сохранёнными dimensions обычно показывай полную строку со всеми существующими показателями, даже если они не изменились.

Для NPC без сохранённых dimensions строка появляется только если в этой сцене действительно возник числовой baseline. Не придумывай показатели только ради заполнения footer.

Если несколько dimensions уже существуют, не заменяй их одним новым словом на следующей встрече. Продолжай сохранённую связь последовательно.

Техническое правило устойчивости: случайно пропущенная видимая строка не должна стирать сохранённые отношения и не должна превращать весь игровой ход в ошибку сервера. Если строка присутствует, её значения должны быть согласованы с сохранёнными dimensions.

## ПРИМЕР НЕПРАВИЛЬНО
Первая сохранённая встреча:
`Эдриан - симпатия 35; доверие 18; влечение 42`

Следующая встреча без причинной перемены:
`Эдриан - интерес 70; нежность 55`

Так нельзя. Это не развитие, а потеря сохранённой связи.

Правильно продолжить прежние dimensions и изменить только реально затронутые:
`Эдриан - симпатия 37/+2; доверие 18; влечение 44/+2`

Также неправильно создавать `настороженность 1` или `уважение 1` для случайного присутствующего NPC только потому, что формат требует число.

## ПЕРЕД COMMIT
Проверь:
1. каждый присутствующий NPC был отдельно оценён с учётом характера, знаний и ситуации;
2. существующие сохранённые dimensions не исчезли и не были заменены новым набором;
3. новый baseline появился только если сцена реально сформировала отношение;
4. числа изменились только если сцена причинно на них повлияла;
5. отсутствие NPC не обнулило связь;
6. поведение NPC соответствует не только цифрам, но и характеру, целям, знаниям и обстоятельствам.
