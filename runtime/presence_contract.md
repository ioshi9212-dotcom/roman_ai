# SCENE PRESENCE CONTRACT

Это обязательный глобальный контракт присутствия и восприятия персонажей в сцене.

## КАНОНИЧЕСКИЙ СОСТАВ СЦЕНЫ
В начале каждого хода `present_character_ids_at_turn_start` и `scene_presence.start_present_character_ids` являются каноническим списком персонажей, которые физически находятся в текущей сцене/локации на момент начала хода.

Для каждого ID обязательно используй:
- имя и роль из `character_registry`;
- полную карточку из `present_character_cards` / `all_character_cards`;
- `current_state` и location из state;
- личную память из `memory_full.characters[character_id]`;
- отношение к POV из relationship lens/state.

Нельзя забывать персонажа только потому, что текущий абзац сфокусирован не на нём.

Персонаж не исчезает из сцены из-за смены фокуса, молчания, небольшого перемещения или отсутствия реплики.

Персонаж перестаёт считаться присутствующим только после реально установленного ухода или физического разделения сцены.

## СТРУКТУРНЫЕ ПЕРЕХОДЫ ПРИСУТСТВИЯ
Состав сцены не пересобирается каждый ход из того, кого автор вспомнил упомянуть.

Сервер считает финальный roster по формуле:
`start roster + enter - leave`.

Для изменения физического состава/положения используй `extracted.presence_updates`:
- `action: enter` только для реального входа;
- `action: leave` только для реального ухода;
- `action: move` для перемещения внутри той же сцены без выхода.

Для `enter`/`move` можно добавлять `zone`, `position`, `distance_to_pov`, `note`, если это полезно пространственной непрерывности.

Если никто не вошёл, не вышел и не поменял важное положение, `presence_updates` может быть пустым: стартовый roster переносится автоматически.

`state_patch.current.present_characters` не удаляет уже присутствующего персонажа только из-за отсутствия его ID в новом списке. Удаление требует явного `action: leave`.

POV нельзя удалить из текущего roster.

## PRESENCE SWEEP
Перед каждым содержательным битом сцены внутренне пройди по каждому персонажу, который всё ещё присутствует.

Для каждого проверь:
1. положение относительно происходящего;
2. доступность зрения;
3. доступность слуха;
4. особые сенсорные способности и их ограничения;
5. хватает ли его знаний для правильного понимания события;
6. должна ли по характеру, целям, отношениям и состоянию возникнуть внешняя реакция.

Если реакция должна быть заметна POV, покажи её.

Не заставляй каждого NPC говорить после каждой фразы. Presence sweep нужен только чтобы никто не превращался в невидимую мебель.

## ПРЯМОЕ ВНИМАНИЕ POV
Если POV явно направляет внимание или действие на конкретного NPC, этого NPC нужно проверить первым.

Если персонаж мог заметить действие и по его характеру оно значимо, нельзя вести сцену дальше так, будто его там нет. Реакция выбирается по карточке, отношениям и ситуации.

## СЛУХ И ДИСТАНЦИЯ
Физическое отдаление не равно выходу из сцены.

Обычный персонаж слышит только то, что реалистично доступно по расстоянию, громкости, стенам, шуму и положению.

Особое восприятие работает только в пределах канонических условий и ограничений.

Смена текстового фокуса не меняет реальную доступность восприятия.

## NPC ВИДЯТ И ДРУГ ДРУГА
Сцена не является туннелем `POV <-> один выбранный NPC`.

Присутствующие персонажи могут воспринимать и учитывать действия друг друга.

Перед важным действием одного NPC учитывай, кто ещё находится рядом и что они могут воспринять.

## НЕВИДИМАЯ МЕБЕЛЬ ЗАПРЕЩЕНА
Если присутствующий персонаж несколько значимых битов подряд полностью не учитывается, хотя происходящее должно попадать в его внимание, это ошибка сцены.

Исправление не требует обязательной реплики. Достаточно естественного внешнего участия или реакции, если она соответствует персонажу.

Отсутствие реакции допустимо только если оно следует из характера, состояния или ситуации.

## ПРИСУТСТВИЕ МЕЖДУ ХОДАМИ
`present_character_ids_at_turn_start` переносит физический состав сцены из state.

Не удаляй персонажа из `current.present_characters` только потому, что он не получил реплику в текущем ходе.

Небольшое перемещение внутри сцены означает `move`, а не `leave`, если явно не установлено обратное.

Если персонаж реально вошёл или вышел, это должно быть отражено в сцене и в `presence_updates`.

## ПЕРЕД ЗАВЕРШЕНИЕМ СЦЕНЫ
Сделай финальный roster check:
1. возьми всех `scene_presence.start_present_character_ids`;
2. добавь только реально вошедших;
3. убери только реально вышедших;
4. `move` не меняет membership сцены;
5. проверь физическое присутствие каждого оставшегося;
6. проверь доступное восприятие каждого значимого события;
7. не раздавай недоступные знания;
8. не лишай знания того, кто объективно мог его получить.

Главное правило: СМЕНА ФОКУСА НЕ РАВНА ИСЧЕЗНОВЕНИЮ ПЕРСОНАЖА.
