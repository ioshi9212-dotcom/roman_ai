# Карточка персонажа v1: что изменили и зачем

**Статус:** черновик. Не подключать к API без отдельной адаптации и тестов.

## Основное решение
Записанный автором характер нельзя сжимать в «удобную» характеристику. Поэтому `character_card.v1.json` хранит **один набор точных цитат** (`канонические_фрагменты`) и **ссылки на них по темам** (`тематические_индексы`).

Пример: автор пишет «Его бесит, когда ему указывают, и он может нахамить даже близким». Это должно оставаться ровно такой фразой, даже если относится одновременно к разделам «характер» и «поведение в конфликте». Не писать вместо неё «не любит контроль, иногда резок».

## Как заполнять
1. Сохрани полный RAW как неизменяемый отдельный источник с версией и SHA-256. В публичный GitHub персональные анкеты не записывать.
2. Выдели фрагменты **буквально** без удаления неудобных выражений. `quote` является точной подстрокой соответствующего RAW. `raw_start/raw_end` показывают диапазон в исходном тексте; при реализации явно зафиксировать единицу отсчёта (например, смещения Unicode-кодовых точек). Если источник составной, указывай отдельный ID сообщения/файла.
3. Дай фрагменту ID и отметь подходящие темы. При нескольких темах повторяй только ссылку на ID, не переписывай текст.
4. Неизвестные сведения не заполняй. Предложения ИИ всегда остаются в отдельном массиве и не становятся каноном без явного разрешения автора.
5. Личная память, приобретённые знания, текущая одежда, местонахождение и меняющиеся отношения хранятся отдельно, не перезаписывая исходную карточку.
6. Для POV исходный канон сохраняется так же, но это **не разрешение GPT самостоятельно задавать мысли, чувства, решения и реплики игрока**.
7. Неизвестные персонажу тайны не становятся его знаниями; у режиссёра и у персонажа разные границы доступа.

## Чего этот черновик ещё НЕ делает
- Не подключает структуру v1 к текущим функциям Roman AI. `app/profile_templates.py`, сериализация и API пока используют старый формат.
- Не гарантирует полное отсутствие смысловых подмен автоматически: точность цитат можно проверить программно, полноту и отсутствие умолчаний нужно контролировать отдельно.
- Не определяет окончательную структуру для памяти и отношений.

## Вопросы, которые оставляем до обсуждения
- Нужны ли отдельные свободные текстовые поля для быстрой читабельности человеком, если **авторские цитаты уже сохраняются полностью**?
- Какой объём полного характера реально отправлять писателю за один ход, чтобы не терялись индивидуальность и сцена?
- Разделять ли общие сюжетные ограничения и личные ограничения героя в разных документах?
